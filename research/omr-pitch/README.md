# 오선보 음높이 기하학적 검출 — 연구 폴더

앱(`index.html`)과 무관한 별도 실험. **아직 앱에 붙이지 않았다.**

## 배경

앱은 지금 Gemini Vision으로 코드·가사·멜로디를 한 번에 읽는다. 코드·가사는
정확하지만 멜로디 음높이가 종종 틀린다(오선의 몇 번째 칸인지는 AI에게
언어 문제가 아니라 좌표 문제라서). 그래서 "AI에게 묻지 말고 재면 어떨까"를
시험했다.

## 결론

**원리는 맞다. 구현은 아직 실전 투입 수준이 아니다.**

| 항목 | 결과 |
|---|---|
| 줄간격 추정 | 작동 (수직 런렝스 + 중간값 정합) |
| 단 검출 | 고해상도 6/6 · 저해상도 1/6 (표본 부족으로 불안정) |
| 음높이 계산 | 정확 — 순차진행 비율 0.96 |
| 음표머리 검출률 | 약 50% ← 병목. 빔으로 이어진 8분음표에서 절반을 놓침 |

자세한 수치와 시도한 방법은 `RESULTS.md` 참고.

## 다음에 이어서 할 사람에게

1. **악보 20~30장으로 검증 세트부터 만들 것.** 지금은 표본이 2장이라
   임계값을 조정할 때마다 한쪽이 좋아지면 다른 쪽이 무너지는 상태다.
   각 장에 정답(단 수, 음표 수)을 손으로 매겨야 한다.
2. 음표머리 검출을 분류기 기반으로 바꿀 것 (지금은 규칙 기반 침식+연결요소).
   빔 분리가 핵심 병목.
3. 이 방향 대신 **oemer/Audiveris를 Hugging Face Spaces 무료 티어에
   올리는 게 더 빠를 수 있다** — 이 프로토타입이 부딪힌 문제들을
   그 엔진들은 이미 해결해 놓았다. `RESULTS.md` 결론 참고.

## 이미 앱에 있는 것 (혼동 방지)

앱의 `melScore()` 함수(v48 기준, index.html 내부)가 이미 멜로디 채점을
한다 — 박자표 불일치·음역 이탈·옥타브 도약을 보고 낮으면 자동 재인식,
의심 음표는 화면에 동그라미로 표시한다. 이 폴더의 기하학적 방식과는
접근이 다르다(하나는 AI 결과를 사후 채점, 하나는 이미지에서 직접 측정).
둘을 합칠 여지는 있지만 아직 통합하지 않았다.
