# 오선보 음높이 기하학적 검출 — 실측 기록

무료·서버 없이 음높이를 직접 재는 방식을 실제 악보로 시험한 기록.
전부 측정값이다.

## 결론 먼저

**"오선 줄 위치를 파악할 수 있다"는 말은 맞다.** 확인했다.
다만 **음표머리를 다 찾는 것**이 남았고, 그게 전체 작업의 대부분이다.

| 단계 | 상태 |
|---|---|
| 줄간격 추정 | **작동** (수직 런렝스 + 중간값 정합) |
| 단 검출 | 고해상도 **6/6** · 저해상도(5px) **1/6** |
| 음높이 계산 | **정확** — 순차진행 비율 **0.96** |
| 음표머리 검출률 | **약 50%** (56/약110) ← 병목 |

## 저해상도는 복원 가능한가 — 그렇다

처음에 "620px 사진은 정보가 소실됐다"고 판단했는데 **틀렸다.**
원본 행 밀도를 직접 보면 오선이 살아 있다.

```
143행 0.34   ← 1번째 줄
148행 0.13   ← 2번째 줄 (희미)
153행 0.18   ← 3번째 줄
158행 0.20   ← 4번째 줄
163행 0.14   ← 5번째 줄
                간격 약 5.1px
```

밀도가 0.13까지 떨어지지만 **주변 중간값을 빼면(배경 제거) 또렷한 봉우리**가 된다.
"전역 최대 밀도의 45% 이상"이라는 절대 임계값을 쓴 것이 실패 원인이었다.

## 고친 세 가지 (모두 원리적 수정, 임계값 조정 아님)

1. **줄간격을 런렝스로 추정** — 여러 간격을 훑어 최고점을 찾는 방식은
   저해상도에서 **간격의 절반을 집는 배음 오인**이 난다.
2. **점수를 합계 대신 중간값으로** — 합계를 쓰면 진한 줄 하나가 점수를 끌어올려
   엉뚱한 간격이 이긴다. 실제로 5.1px 악보에서 3.25px를 골랐다.
   중간값은 5줄이 전부 있어야 높아지므로 이 함정이 없다.
3. **배경 제거 후 봉우리 탐색** — 절대 밀도 임계값을 버렸다.

## 남은 병목: 음표머리 검출률 약 50%

찾은 음의 음높이는 정확하다(순차진행 0.96). 문제는 절반을 놓치는 것.
원인은 **빔으로 이어진 8분음표** — 이 악보는 대부분이 빔 묶음이고,
세로 침식이 빔을 자르면서 음표머리도 손상된다.

시도한 방법과 수치:

```
세로 침식 + 연결요소   56개  순차진행 0.96  ← 현재. 정밀도 높고 검출률 절반
타원 템플릿 정합      159개  순차진행 0.59  ← 검출률 올랐지만 오탐 급증
             (완화)  780개  순차진행 0.42  ← 사용 불가
```

**개수를 늘리면 정확도가 무너진다.** 이 벽을 넘으려면:
음표머리 전용 분류기(CNN 또는 정교한 규칙), 빔·기둥 분리,
한 기둥에 여러 머리(화음), 속 빈 머리 대 채운 머리, 점음표, 임시표 귀속.

## 저해상도 단 검출 1/6 — 왜 아직 안 되나

줄간격 정밀화 격자를 0.25 → 0.1로 촘촘히 하면 저해상도가 좋아지는데
**고해상도가 6단 → 3단으로 무너진다.** 임계값 조합 16가지를 격자 탐색해도
두 장을 동시에 만족시키는 조합이 없었다.

이건 임계값 문제가 아니라 **표본이 2장뿐이라는 문제**다.
악보 20~30장으로 검증 세트를 만들지 않으면 계속 이 상태로 오락가락한다.

## 다음에 할 일 (이 순서로)

1. **악보 20~30장 수집** — 해상도·인쇄품질·기울기가 다양해야 한다.
   각 장에 정답(단 수, 음표 수)을 손으로 적어 검증 세트를 만든다.
   **이게 없으면 어떤 개선도 개선인지 알 수 없다.**
2. 음표머리 검출을 분류기 기반으로 교체 (빔 문제 해결)
3. 그 다음에야 리듬(기둥·꼬리·빔 분석)

    순차진행 비율 = |Δ오선단계| <= 2 인 인접쌍 비율
    간격 균일성   = x간격이 중간값의 0.45~2.6배인 비율

    이 프로토타입의 기하학 검출: 순차진행 0.96  ← 신뢰 가능
    오탐이 섞인 경우:            순차진행 0.42  ← 사용 불가
